# 读线 · PaperLine

[English](README.en.md) · 简体中文

一个本地运行的论文学习工作台。以论文为证据维护**共享方法与概念**，用**模型家族演进线**组织独立阶段，并在阶段下记录论文与方法贡献；研究阅读线保留已有的知识与学习记录。

## macOS 原生桌面版（0.3.15）

0.3.15 把思想图改为“融会贯通全图”：像论文地图一样，一屏画出所有方法，实线为已确认关系，虚线为推荐联系，点虚线即可确认；选中方法时其余方法淡出。“聚焦当前方法”保留原关系图，下方的相关推荐、论文、阶段与流动、对比改为标签页，只展开一项，页面不再需要长距离滚动。方法目录在全图模式下收起，输入搜索时展开。有联系的方法按连通分组紧凑排布，尚无联系的方法默认收起，可点按钮展开；推荐计算结果会缓存，切换选中方法不再重算。

0.3.14 在思想图中推荐“可能相关的方法”：依据同被论文使用、来源论文间引用、共同关联和描述相似度推断，并写明理由；可一键建立关系、加入对比或忽略（忽略记录仅保存在本机）。新增方法对比，可并排查看 2–4 个方法的理解、机制、思考、资料与演进线；选两个方法时可将异同保存为“对比”关系。思想关系新增“本质相同”“替代方案”“组合使用”；方法所在阶段按日期排序，出现在多条演进线时显示跨线流动顺序。使用新关系类型后，备份不能导入 Windows 0.3.13 等旧版本。无需数据迁移。

0.3.13 扩展思想图搜索，覆盖名称、别名、方法定义、核心机制和我的思考。多个关键词可用空格、逗号、顿号或分号分隔，并跨字段共同匹配；输入搜索时保留当前方法和编辑草稿。

0.3.12 将思想图的“编辑方法与笔记”移到右侧，选择方法即可编辑当前内容；切换方法、查看论文与返回阅读线时，详情随选择更新，草稿与现有关系继续保留。

0.3.11 将阅读线的“关联已有卡片”改为可搜索的卡片选择器，直接查看名称、分类、状态和简介；点击“加入”即可连续关联，已加入的卡片会明确标记。只增加阅读线归属，卡片内容与阶段贡献保持原样。

0.3.10 将思想图顶部的方法选择区改为卡片列表，直接显示名称、分类、状态和简介；方法目录支持纵向浏览，选择方法后保留目录位置。此更新只调整思想图展示，存档结构与现有关联保持不变。

0.3.9 修复新建思想卡无法选择模型演进线的问题，并在演进时间线下显示本线思想卡。这些卡片不自动归入任何阶段；使用现有存档结构，无需数据迁移。

0.3.8 的阶段资料支持论文、网页和模型。论文继续从库中搜索，网页或模型可直接新建、编辑并关联方法；网页填写来源链接，模型可以先不填。资料类型、链接和说明随备份与 Obsidian 导出保留，网页和模型不进入论文引用地图。

0.3.7 支持单击方法，在右侧查看和编辑；双击阅读线方法节点或点击“打开思想图”进入完整思想图。

0.3.6 固定顶部导航，提供阅读线上下排序按钮，并修正整页缩放后的底部留白。从阶段论文新增方法会直接显示在当前阶段；已保存的方法关系可以点击“加入本阶段”，保留原有依据和来源。

阶段日期使用应用内日历，随整页缩放；也可以直接输入日期。

0.3.5 将类型、状态和其他固定选项直接展示为可见按钮；阶段论文支持连续添加多篇，完成后再关闭选择器。

0.3.5 补强故障恢复：云端恢复会检查下载期间的本机编辑；主数据损坏时，仅在备份有效时提供明确的恢复入口，保留损坏文件供排查。草稿按编辑对象隔离，重复点击保存不会重复创建；超过 20 MB 的请求保留后台会话，备份写入失败保留原文件。

原生版使用 Tauri 2 与 macOS 自带 WebView，Python 后端随应用一起打包，通过标准输入输出通信，不启动本地 HTTP 端口。安装后不需要 Python、Node.js 或项目源码。重复打开会聚焦已有窗口，关闭窗口即退出后台进程。

在 macOS 13 或更新版本上打开 DMG，将应用安装到 `/Applications/PaperLine.app`，以后只从这个位置启动。升级前正常退出旧版。项目根目录的 `PaperLine.app` 是保留的旧浏览器启动器；不要把构建目录或版本目录内的 `.app` 当作新的安装入口。

原生数据目录为 `~/Library/Application Support/io.github.applespriter.paperline/`；升级、移动应用不会改变这个路径。首次使用可在“设置”导入旧版 `data/state.json` 或通过旧版导出的 JSON 备份。Mac 0.3 使用 schema 2：首次启动会只读导入同目录旧 `state.json`，写入独立的 `state-v2.json`；原文件保留，后续直接读取 v2。备份、Obsidian 目录选择与确认操作使用系统对话框；论文网址与 Zotero 链接交给浏览器或 Zotero 打开。

构建需要 Apple Silicon Mac、Xcode Command Line Tools、Node.js/npm、Rust stable 与 Python 3.10+。仓库内 `.desktop-tools/cargo/bin`、`.desktop-tools/rustup`、`.desktop-tools/venv` 若已安装，会自动复用；否则使用 PATH 上的 Rust 与 Python，并在 `.desktop-tools/venv` 创建打包环境。

```bash
npm ci
npm run desktop:package
```

输出到 `dist/macos/0.3.15/`：`PaperLine_0.3.15_aarch64-apple-darwin.dmg` 和压缩的 `.app.zip`。不再保留可直接启动的版本目录 `.app`；构建目录的临时 bundle 在打包验证后清理。DMG 通过 `hdiutil` 无界面生成，包含应用与“应用程序”快捷方式。`npm run desktop:dev` 启动开发版。构建只打包 `static/` 与独立后端，不包含 `data/`、WebDAV 凭据或本地日志。首次构建会下载 Cargo 依赖与 PyInstaller。打包前会检查 Python 可执行文件与动态库的最低 macOS 版本；若高于 13.0 会终止构建。可以通过 `PAPERLINE_PYTHON=/path/to/python3.13 npm run desktop:package` 指定兼容的 Python；已有构建环境使用其他解释器时，须先重建 `.desktop-tools/venv`。当前默认使用本机 ad-hoc 签名并保留 Hardened Runtime；由于打包的 Python 动态库没有 Team ID，应用仅添加 `disable-library-validation` 例外（Tauri 对主程序与侧车共用同一 entitlement 文件）。打包脚本会再次运行已签名应用内的后端，检查启动、API 与退出；对外分发前需要 Developer ID 签名与 Apple 公证。

macOS 构建会把 Rust 二进制中的本机构建路径匿名化为通用 `/build` 前缀，并在打包前检查后端归档隐私。

开发部署可执行 `python3 scripts/install-macos.py /Volumes/PaperLine/PaperLine.app`。脚本先检查 bundle ID 与签名，要求正常退出正在运行的 PaperLine，把旧正式应用压缩到 `.desktop-build/install-backups/`，再原子替换 `/Applications/PaperLine.app`；替换后签名验证失败会回滚。它不修改 AppSupport、Keychain、Obsidian 或旧浏览器启动器。恢复时先用 `ditto -x -k <备份.zip> <临时目录>` 解压旧 bundle，再用同一安装脚本替换正式应用。

## Windows 桌面版（0.3.15）

Mac 与 Windows 版本独立：Mac 为 0.3.15，Windows 为 0.3.15。Windows 同步使用时间线、模型阶段、全局方法与论文搜索的共享实现；其有效版本由 `src-tauri/tauri.windows.conf.json` 指定。

目标为 Windows 10/11 x64。安装器采用 NSIS，为当前用户安装，无需单独安装 Python 或 Node.js；可选择简体中文或英文。缺少 WebView2 时，安装器会下载微软官方 bootstrapper，因此首次安装可能需要联网。应用数据存放在 `%APPDATA%\io.github.applespriter.paperline\`，与安装目录分开。旧版 JSON 数据可以从“设置”导入。

在 Windows 本机安装 Python 3.13 x64、Node.js/npm、Rust stable MSVC，以及 Visual Studio Build Tools 的“使用 C++ 的桌面开发”和 Windows SDK，然后在项目目录的 PowerShell 执行：

```powershell
npm ci
npm run desktop:windows:package
```

需要指定解释器时，先设置 `$env:PAPERLINE_PYTHON = "C:\path\to\python.exe"`。打包脚本使用独立的 `.desktop-tools/venv-windows`，生成 `paperline-backend-x86_64-pc-windows-msvc.exe` 并通过标准输入输出测试；不会打包真实 `data/`、账户信息或日志。输出为 `dist/windows/0.3.15/PaperLine_0.3.15_x64-setup.exe` 与 `SHA256SUMS.txt`。`npm run desktop:windows:dev` 启动开发版。Windows 后端必须在 Windows 编译，不能用 macOS 的 PyInstaller 产物替代。

`.github/workflows/windows-desktop.yml` 运行 Node、Python、Rust 测试，构建前后审计 Python archive 与原生可执行文件中的私有构建路径，再打包 NSIS。在专属 CI runner 中，安装验收先将已发布的 0.2.1 安装到含中文和空格的路径，在默认 `%APPDATA%` 目录创建合成 v1 笔记，再升级到 0.3.15。检查覆盖只读 v1 迁移、手工方法与阶段贡献、阅读记录、重装和卸载后数据字节一致、真实窗口、正常退出及所属子进程清理。合成默认数据目录在开始时必须不存在，并在结束后清理；不使用真实 Zotero/WebDAV 凭据。通过后上传安装器及校验和作为 GitHub Actions artifact，不发布 Release。

Windows 0.3.15 的安装器须通过本轮 workflow 后才算完成验证。[历史 0.2.1 CI](https://github.com/AppleSpriter/PaperLine/actions/runs/38501863099) 不代表 0.3.15 已通过。草稿序列化与恢复由 JavaScript 测试覆盖；原生 WebView 草稿跨升级保留、Zotero、目录选择、备份保存及完整界面仍需 Windows 实机验收。现阶段没有 Windows 代码签名证书，未签名安装器可能触发 SmartScreen。设计依据：[Tauri 官方 Windows installer 文档](https://v2.tauri.app/distribute/windows-installer/)。

## 浏览器版运行

需要 Python 3.10 或更新版本，无需安装依赖。

仓库中的旧浏览器启动器与 `stop.command` 保留作源码兼容用途，不作为 Mac 0.3 的安装或日常启动入口。Mac 原生版只从 `/Applications/PaperLine.app` 启动。

也可以双击 `start.command`，在终端前台运行；关闭该终端即可停止服务。其他系统在项目目录执行：

```bash
python3 app.py
```

应用会在浏览器打开 `http://127.0.0.1:8765`。

右上角的“帮助”随时打开完整使用说明，包含概念、上手步骤、Zotero 与 Obsidian 配置和快捷键。

## 首次使用

模型家族演进线以时间线展示阶段日期、论文和方法贡献连线。论文库可搜索已导入的论文，再打开论文或加入阶段。方法是全局共享实体：不同论文与阶段引用同一方法，修改后各处保持一致。

1. 创建一条阅读线，写下要研究的问题。
2. 在“搜索”里一个框同时搜阅读线、思想卡和论文，结果按类型用左侧色条和标签区分（思想卡绿色、阅读线蓝色、论文紫色），点一下直接跳到对应位置；选了状态筛选时只看思想卡。添加新卡时也会显示相近卡片。思想卡可以设置别名，并同时属于多条阅读线。
3. 在“论文库”搜索本机 Zotero，导入论文；也可以手动添加。选择论文后，可读取其文字批注并从批注建卡。
4. 把多篇论文关联到同一张卡，并为每条关系写下具体用法和原文位置。遇到新问题时点击“引申新卡”，新卡会自动连回来源思想。
5. 点击“开始读”，结束时用自己的话写两句，再留下一个下次要弄清的问题。下次打开这张卡时会先看到上次的记录。
6. 在“设置”填写 Obsidian 库目录，点击“导出到 Obsidian”。

可以在设置中切换界面语言（简体中文 / English），也可以指定每日提醒时间。应用页面保持打开时会弹出站内提醒；按需开启浏览器通知。Obsidian 笔记中自动生成的栏目标题会使用当前界面语言；已有笔记中手写的内容不会被改写。

卡片编辑会保留草稿，切换卡片或刷新页面后可以继续写。阅读时点击“稍后继续”会保留计时和感想，再次打开同一张卡即可继续，中间休息的时间不会计入阅读。草稿存于当前浏览器，点击“保存卡片”或“保存本次阅读”后才会写入应用数据并纳入备份与导出。

卡片的类型和状态是一排按钮，点一次立即保存，不需要再点“保存卡片”；正文仍按草稿处理。

在阅读线视图里用每行的 ↑ ↓ 调整学习顺序。每张卡会累计阅读时长，卡片详情显示总时长和次数，阅读线顶部显示整条线的累计时长。

同时开着两个页面时，切回页面会自动载入最新数据。如果一张卡在别处已经改过，保存时会提示并载入新版本，你写的内容保留为草稿，确认后再点一次保存即可覆盖。

论文地图的年份模式按年份分列，并用连线显示引用时间轴；也可切换为库内被引次数排序。选中论文后显示三栏：左侧是它引用的论文，中间是当前论文，右侧是引用它的论文；“返回全库”恢复之前的排序。桌面端详情固定在侧栏，窄屏端使用详情抽屉。推荐论文来自至少两篇库内论文的参考文献证据。旧版数据会直接用已保存的引用关系与参考文献重建推荐，无需再次同步 Zotero。

论文地图和思想图内可按住 macOS 的 Command 或 Windows 的 Ctrl 并滚动鼠标滚轮缩放（15%–200%）；普通滚轮仍用于滚动，缩放以鼠标位置为中心。

右上角“整页”按钮可调整整个界面至 70%–150%，点击百分比恢复 100%；比例在本机保存，与图谱独立缩放互不影响。

## 删除与快捷键

- 思想卡：右侧详情底部的“删除这张思想卡”。它的论文关系、思想关联和阅读记录会一并删除。
- 论文：右侧详情底部的“删除这篇论文”。只删除它与思想卡的关系，思想卡本身保留。
- 阅读线：在“编辑阅读线”弹窗里点“删除阅读线”。思想卡、论文和阅读记录都会保留。
- 删除后再次导出，会把之前由应用管理的对应 Obsidian 笔记移至库内 `.trash/PaperLine/`，可恢复整篇笔记和手写补充。其他手写笔记不会被清理。
- 快捷键（没有弹窗且焦点不在输入框时）：`1`–`4` 切换思想图 / 阅读线 / 搜索 / 论文库，`n` 新建思想卡，`p` 添加论文，`l` 新建阅读线，`s` 开始阅读当前卡，`/` 跳到搜索，`?` 打开使用说明。

Zotero 须保持开启，并在 **设置 → 高级**中启用“允许本机其他应用与 Zotero 通信”。应用只读取 Zotero 的本地接口，不修改 Zotero 资料。

## 数据与导出

模型家族阅读线可关联阶段（标题、日期、摘要），学习记录可指向阶段或保留旧卡片目标。迁移备份会一并携带经过引用与长度检查的阶段、论文批注、新建表单及计时草稿；旧卡片和旧阅读记录草稿仍保留。云端 v2 固定写入 `state-v2.json`，不覆盖旧版 `state.json`。

- 浏览器版数据存放在 `data/state-v2.json`；该目录已被 Git 忽略。
- 每次写入前会把上一份数据复制到 `data/state-v2.backup.json`。主文件损坏时应用不会改动任何数据，并在错误提示里给出这份备份的位置。
- “设置 → 备份数据”可下载完整 JSON 备份；“从备份恢复”可以选一个备份文件替换当前数据。恢复前会检查文件格式和引用是否完整，并把当前数据另存为 `data/state-v2.before-restore-时间.json`。Obsidian 路径、语言和提醒时间沿用本机设置，不从备份带过来。WebDAV 云端 `history-v2/` 里的文件也可以直接拿来恢复。

## WebDAV 云同步

- 在“设置 → WebDAV 云同步”填写地址、用户名、密码和云端文件夹，勾选“自动上传到 WebDAV”，先点“测试连接”确认能写入。
- 开启后，有改动时每 5 分钟自动上传一次 `state-v2.json` 到云端文件夹（从第一次改动算起，5 分钟内的改动合并成一次上传；没有改动就不上传），并在 `history-v2/` 下每天保留一份 v2 历史备份。上传失败会按 1、2、4…最长 15 分钟退避重试；应用启动时和正常退出前也会补传一次。
- 右上角显示“已同步 / 待同步 / 同步失败”，点它打开设置查看原因；“立即同步”可以手动上传。
- 坚果云地址是 `https://dav.jianguoyun.com/dav/`，密码要用它后台生成的“应用密码”。Nextcloud 一般是 `https://你的域名/remote.php/dav/files/用户名/`。
- 账号单独存放在 `data/webdav.json`（权限 600），不会写进 `state-v2.json`、备份下载或浏览器。密码框留空表示沿用已保存的密码；换了地址或用户名就必须重新填写。
- 每次保存都会在数据里记下保存时间 `savedAt`。设置里会显示本机和云端各自的保存时间，以及哪边更新。
- 主文件上传使用条件写入：新建要求云端文件仍不存在，覆盖要求强 ETag 与刚读取的版本一致；同步期间云端有变化会停止并提示冲突。已有不同内容的云端文件缺少强 ETag 时，即使手动确认覆盖也会保守停止，可先从云端恢复或选择空同步位置。旧版备份导入后，首次覆盖不同的 v2 云端内容需明确确认。
- 上传前先比较两边时间：云端比本机新（比如另一台电脑刚传过）时，自动上传会暂停，右上角显示“云端更新”，不会覆盖云端。
- 这时可以点“从云端恢复”，确认后用云端数据替换本机；本机当前数据先另存为独立的恢复前备份。恢复后两边时间一致，自动上传照常继续。
- 也可以点“立即同步”，确认后用本机覆盖云端；被覆盖的云端那份会先存成 `history-v2/state-v2-overwritten-时间.json`。
- 如果本机比云端新，“从云端恢复”会多提醒一句会用较旧的数据替换。两边内容一致时不会恢复。Obsidian 路径、语言和提醒时间始终沿用本机设置。
- 旧版本上传、没有 `savedAt` 的云端文件，按服务器记录的修改时间比较。两台电脑的系统时钟差太多时，判断可能不准。
- 不会自动合并两边的改动：两台电脑都改过时，只能选一边保留，另一边在 `history-v2/` 或 `data/` 里留有副本。建议使用 https 地址，http 会明文传输密码。
- Obsidian 导出位置是所选库的 `PaperLine/`，包含“阅读线”“思想卡”“论文”“模型阶段”四个目录。
- 导出笔记不再包含隐藏 HTML 标记。生成内容的所有权保存在 `PaperLine/.paperline-export.json`；重复导出只替换上次生成的完整内容，保留前后的手写补充，旧标记笔记会自动迁移。如果生成内容被手工修改、出现重复或同名文件无法确认归属，整次导出会在写入前停止并指出冲突文件。请保留该隐藏记录文件。
- 内容没有变化的笔记会跳过、不重写文件，避免 Obsidian 同步整库刷新；导出后会提示本次写入多少篇、跳过多少篇。
- 笔记文件名在创建时按标题生成，之后改标题不会改文件名，以免 Obsidian 里已有的链接失效；笔记正文中的标题会随之更新。
- 论文笔记首次导出会带有你使用的“一句话、解决问题、核心机制、思考、技巧、局限”等栏目。

应用只绑定到 `127.0.0.1`，不需要账号或云服务。图谱和计时都在本机运行。
